# ロギング方針

具体的な保持日数・マスク対象・既定ログレベルは`logging-config.example.json`をコピーした
`logging-config.json`に定義し、本ファイルはその読み込みを前提とした方針のみを記す。
値をこのファイルに直接書き込まない。

## 1. 何を残すか

- 処理の開始・終了・分岐判断・エラーは残す
- `logging-config.json`の`mask_fields`に列挙されたフィールド(パスワード・トークン・個人情報等)は、
  値そのものではなくマスク済みの状態でのみ出力する。列挙が空の場合でも、明らかな機微情報は出力しない
- `security-guard`のシークレット項目と重複する場合はそちらを優先する

## 2. ログレベルの使い分け

- ERROR: 処理が継続できない、または人による対応が必要な事象
- WARN: 処理は継続できるが想定外の状態
- INFO: 処理の開始・終了、外部連携の呼び出しなど、後から追跡したい正常系の節目
- DEBUG: 開発時のみ必要な詳細情報。既定では`logging-config.json`の`default_level`に従い出力しない

## 3. 形式

- 機械可読な構造化ログ(json等)を既定とする。人間可読なテキストログのみで運用する場合は理由を該当システムのシステム単位設計書(docs/システムフォルダ/配下)に残す
- 最低限、時刻・レベル・処理識別子(リクエストID等)・メッセージを含める

## 4. 保管・ローテーション

- 保持日数は`logging-config.json`の`retention_days`に従う。未設定の場合は決めずに「未確定」として運用側に確認する
- `ops-guard`が有効な場合、自動修正ループが参照するログの形式・保存先はこの方針と一致させる
