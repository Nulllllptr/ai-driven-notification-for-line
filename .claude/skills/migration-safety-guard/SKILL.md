# マイグレーション安全ガード

## 1. 段階的手順(Expand → Migrate → Contract)

1. **Expand**: 新しいカラム・テーブルを追加する。既存の読み書きは壊さない
2. **Migrate**: 新旧両方に書き込みつつ、既存データを新形式へ移行する。アプリケーションが新形式を
   読めるようにする
3. **Contract**: 移行完了を確認してから、旧カラム・テーブルを削除する

1回のデプロイで「追加」と「削除」を同時に行わない。途中でロールバックしたとき、旧コードが新
スキーマを読めなくなるため。

## 2. ロールバック手順

- マイグレーションには、適用(up)と同時に取り消し(down)の手順を用意する
- ロールバックスクリプトは、少なくとも一度は非本番環境で実行して動作を確認してから本番に適用する

## 3. 後方互換性

- デプロイ中は新旧のアプリケーションコードが同時に稼働する前提で設計する(段階的ロールアウト・
  カナリアと組み合わせる場合は特に重要。`cicd-guard`と連携する)
- 旧コードが新スキーマを読んでもエラーにならないか、新コードが旧スキーマを読んでもエラーに
  ならないかを、実装前に確認する

## 4. 大規模データ移行

既存データを書き換える移行は、対象件数が大きい場合バッチに分割し、途中で止めても再開できる設計に
する。ロックを長時間保持する一括更新は避ける。

## 5. 対象外

特定のマイグレーションツール(Flyway/Alembic/Prisma Migrate等)固有の操作コマンドはここでは扱わない。
原則のみを扱う。
