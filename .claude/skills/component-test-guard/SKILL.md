# コンポーネントテストガード

## 1. 位置づけ

`dev-method-guard`は「テストを先に書くか後に書くか」という順序を選ぶ。本スキルは順序に関わらず、
コンポーネント単体で「何をテストし、どこに記録するか」を規定する。両者は独立して併用する。
公開直前の重大度別レビューは`release-review-guard`、随時のコード品質レビューは`code-review-guard`が
別途扱う。本スキルは「壊れていないことの実行確認」を扱う。

## 2. ドライバによる単体実行確認

コンポーネントは独立して作られる前提のため、上位モジュール(呼び出し元)が未実装・未接続でも、
テスト用の呼び出し元(ドライバ)を用意して単体で実行確認する。ドライバは本番の呼び出し元を
簡略化したスタブでよい。使用したドライバの概要は記録に残す(4節)。

## 3. テストする観点

| 観点 | 内容 |
|---|---|
| 条件網羅テスト | 分岐・境界値を網羅する。仕様書「3. 入力」「4. 出力」の条件を全て通す |
| 機能要件テスト | 仕様書に書かれた入出力の仕様通りに動くか |
| 非機能要件テスト | 仕様書「6. 制約・注意事項」に記載がある場合のみ実施。記載がなければ「該当なし」と明記する |

## 4. 記録

`COMPONENT_TEST_TEMPLATE.md`をコピーし、対象コンポーネント仕様書と同じフォルダに
`docs/システムフォルダ/<番号>-<コンポーネント名>-テスト.md`として生成・更新する。
テストケース(入力・期待値)と実施結果(実際値・pass/fail・実施日)を両方記録する。
実施結果は上書きせず、失敗した記録を残したまま再実施分を追記する。

## 5. 繰り返さない条件

直近のテスト記録が今回の変更点を既にカバーしている場合、再実施は不要。
コンポーネントの入出力仕様が変わった場合のみ、該当ケースを再実施する。
