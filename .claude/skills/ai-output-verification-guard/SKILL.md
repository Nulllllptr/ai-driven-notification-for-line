# AI出力検証ガード

`implementation-guard`が実装の開示義務を扱うのに対し、本スキルは「AIの出力そのものが事実か」を扱う。

## 1. パッケージ・ライブラリの実在確認

- 新規に追加する外部パッケージは、実装前に公式レジストリ(npm/PyPI等)で実在を確認する。
  確認できない場合、AIが記憶から推測した「幻覚パッケージ」の可能性を疑う
- 確認できないパッケージ名は、実在を確認できるまで実装に含めない
- 有名パッケージに酷似した無名パッケージ(スロップスクワッティングの標的になりやすい)は特に疑う

## 2. API・設定項目の実在確認

外部API・ライブラリの関数・設定項目を使う場合、公式ドキュメントで実在と仕様を確認してから実装する。
記憶のみに頼って実装しない。確認できない場合は「未確認」と明示し、断定で書かない。

検索しても根拠(公式ドキュメント・信頼できる情報源)が見つからない場合、実装せず開発者に「根拠なし」と
伝えるか、それでも試行的に実装する場合は次の2点を必ず併記する。省略しない。

- この実装には根拠(公式ドキュメント等の裏付け)がなく、試行的なものであること
- それでもなぜ正常に動作すると考えるか(推測の根拠・類推元)

## 3. 生成コードの評価ハーネス

AIが生成したコード、特にテストコードは次を満たすか確認する。

- テストが実際に検証したい振る舞いを検証しているか(常に真になるだけのアサーションになっていないか)
- 生成されたテストの結果だけで正しさを判断せず、実データ・実環境の結果とも突き合わせる

## 4. モデルバージョンの固定

本番で稼働するLLM呼び出し(要約・分類・生成等)がある場合、使用モデルのバージョンを固定し、
変更時は影響確認のうえ明示的に切り替える。無断のモデル自動更新に振る舞いの変化を委ねない。

## 5. 対象外

特定のパッケージマネージャ・レジストリの操作コマンド自体はここでは扱わない。実在確認の原則のみを扱う。
