# /adopt-template: 既存プロジェクトへの非破壊移植

引数: $ARGUMENTS

コピー元の`.claude/`一式を、コピー先の`.claude/`に**非破壊で**移植する。コピー先に既に存在する
ファイル・設定は一切変更しない。「コピー先の内容を優先し、コピー先にない機能だけを補う」が原則。
`--dry-run`が指定された場合、実際の書き込みは行わず、4節の判定結果のみを提示する。

## 1. 開始前の確認

- コピー元・コピー先のパスが引数で与えられていない場合、実装せずその場で聞く。推測で進めない
- コピー先に`.claude/`自体が存在しない場合、これは新規導入であり本コマンドの対象外。
  コピー元の`.claude/`をそのまま丸ごとコピーしてよい旨を伝え、コピー後は`design-doc-guard`の
  通常フロー(新規プロジェクト導入)に委ねて終了する
- コピー先がgitリポジトリの場合、コミットされていない変更がないか確認する。ある場合は
  「非破壊操作だが念のため」の理由を添えて、先にコミットまたはstashするか開発者に確認する

## 2. 比較対象

コピー元・コピー先それぞれの`.claude/`直下で、次をディレクトリ・ファイル名単位で比較する。

| 対象 | 単位 | 判定基準 |
|---|---|---|
| `skills/<name>/` | ディレクトリ名(`<name>`) | 同名ディレクトリがコピー先に存在するか |
| `rules/<file>` | ファイル名 | 同名ファイルがコピー先に存在するか |
| `commands/<file>` | ファイル名 | 同名ファイルがコピー先に存在するか |
| ルート直下の`*_TEMPLATE.md`等 | ファイル名 | 同名ファイルがコピー先に存在するか |
| `CLAUDE.md` | ファイル全体ではなくセクション単位(3節) | 3節に従う |

## 3. 判定・コピー

skills/rules/commands/ルートテンプレートについて、それぞれ次のいずれかに分類する。

- **コピー先に存在しない** → コピー元からそのままコピーする(ディレクトリ単位。SKILL.mdと
  同梱のconfig.example.json等をまとめて運ぶ)。追加リストに記録する
- **コピー先に既に存在する** → 一切変更しない。コピー先を優先する。スキップリストに記録する
  (中身が同じか異なるかの判定・自動マージは行わない。開発者が手動で見比べる対象として報告するに
  留める)

## 4. CLAUDE.mdのマージ(上書きしない)

- コピー先に`CLAUDE.md`が存在しない → コピー元の`CLAUDE.md`をそのままコピーする
- コピー先に`CLAUDE.md`が存在する → 上書きしない。次のセクションだけを個別に扱う
  - 「ユニット索引」に相当する表がコピー先にある → 3節で新規コピーしたskill/ruleの行だけを
    末尾に追記する。表がない → コピー元の表から、新規コピーした行だけを抜き出して
    「## ユニット索引(ai-driven-dev-templateより導入)」として新設する
  - 「コマンド索引」も同様に、新規コピーしたcommandの行だけを追記または新設する
  - 「最初に行うこと」に相当する記述(設計書・仕様書の起動条件を説明する節)がコピー先に
    既にある → 触れない。似た記述が見当たらない場合のみ、コピー元の該当節を
    「(ai-driven-dev-templateより導入)」と注記して追記する
  - 追記した行・節には、後から見分けられるよう`(ai-driven-dev-templateより導入)`を付す

## 5. dry-runの場合

書き込みを行わず、3節・4節の判定結果を次の形式で提示して終了する。

- 追加予定: [ディレクトリ・ファイル名の一覧]
- スキップ予定(コピー先優先): [ディレクトリ・ファイル名の一覧]
- CLAUDE.mdへの追記予定: [追記するセクション・行の一覧]

## 6. 完了時の報告

- 追加したもの(skill/rule/command/テンプレート)の一覧
- スキップしたもの(同名がコピー先に既に存在したため)の一覧。開発者が手動で見比べるべき候補として明示する
- CLAUDE.mdに追記した内容
- 対象外として扱った`docs/`配下(設計書の実データ)には触れていない旨
