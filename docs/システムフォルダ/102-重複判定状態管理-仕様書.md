# コンポーネント設計書: 重複判定・状態管理

このコンポーネントが属するシステムは`./100-システム仕様書.md`を参照。
対応するテスト成果物は`./102-重複判定状態管理-テスト.md`。

## 1. 目的
配信済み記事の記録を状態ファイルに保持し、101の候補記事から既配信分・類似記事を除外する。
また、配信が確定した記事を状態ファイルへ追記する。

## 2. 説明
2つの公開関数を持つ。
- `filter_undelivered(candidates)`: 101の出力から、状態ファイルに記録済みのurl一致・
  タイトル類似の記事を除外して返す(101→102の経路)
- `record_delivered(articles)`: 103が生成し104が送信した記事を状態ファイルへ追記する
  (104→102の経路、105が送信成功後に呼び出す)

類似度判定は`difflib.SequenceMatcher`によるタイトルの文字列類似度比率(0〜1)を用いる。
LLMは使わない(コストと実行時間を抑えるため。105全体で1回のLLM呼び出しに集約する方針は
103に譲る)。閾値は0.6(初期値、調整可能な定数)とする。

## 3. 入力
- `filter_undelivered(candidates: list[Candidate]) -> list[Candidate]`
  - `candidates`: 101(`news_collector.Candidate`)が返す候補記事リスト
- `record_delivered(articles: list[dict]) -> None`
  - `articles`: `[{"url": str, "title": str}]`形式。103が生成した配信記事
- 状態ファイル: `data/delivered.json`(プロジェクトルート相対、リポジトリにコミットして永続化)

## 4. 出力
- `filter_undelivered`: 未配信と判定された`Candidate`のリスト(元の順序を維持)
- `record_delivered`: 戻り値なし。呼び出し後、`data/delivered.json`が更新される
- 状態ファイルの形式:
```json
{
  "delivered": [
    {"url": "https://...", "title": "記事タイトル", "delivered_at": "2026-08-19T00:00:00Z"}
  ]
}
```

## 5. 依存コンポーネント・外部連携
- 依存コンポーネント: なし(101・103とはデータ形式でのみ結合し、直接呼び出し合わない)
- 外部連携: なし(ローカルのJSONファイル読み書きのみ)

## 6. 制約・注意事項
- 状態ファイルは`delivered_at`が現在時刻から6ヶ月より古いレコードを`record_delivered`実行時に
  取り除く(肥大化防止、システム単位設計書5節)。`filter_undelivered`はレコードの削除を行わない
  (読み取り専用)
- 状態ファイルが存在しない場合は空の状態(`{"delivered": []}`)として扱い、エラーにしない
  (初回実行時に必ず発生するケースのため)
- 状態ファイルの内容が不正なJSON(壊れている)場合は、空扱いにせずエラーを送出する。
  空扱いにすると既配信記事が「未配信」と誤判定され、同じ記事を再送してしまう
  (「一度取得した情報を何度も参照しない」という要件に反する)ため、安全側に倒して
  処理全体を止める
- タイトル類似度は日本語・英語が混在する前提のため、単語分割に依存しない文字列全体の
  類似度比率(`difflib.SequenceMatcher.ratio()`)を採用する。形態素解析等の高度な処理は
  行わない(個人小規模用途には過剰なため)

## 7. 受け入れ条件(EARS形式)

| ID | パターン | 記述 |
|---|---|---|
| AC-1 | ユビキタス | 重複判定・状態管理コンポーネントは、状態ファイルに記録されたurlと一致する候補記事を除外する |
| AC-2 | ユビキタス | 重複判定・状態管理コンポーネントは、状態ファイルに記録されたいずれかのタイトルとの類似度比率が0.6以上の候補記事を除外する |
| AC-3 | イベント駆動 | `record_delivered`が呼び出されたとき、重複判定・状態管理コンポーネントは指定された記事のurl・タイトル・呼び出し時刻(配信日時)を状態ファイルへ追加する |
| AC-4 | イベント駆動 | `record_delivered`が呼び出されたとき、重複判定・状態管理コンポーネントは状態ファイル中の配信日時が6ヶ月より古いレコードを取り除いてから保存する |
| AC-5 | 不具合対応 | 状態ファイルが存在しない場合、重複判定・状態管理コンポーネントは空の状態から処理を開始する |
| AC-6 | 不具合対応 | 状態ファイルの内容が不正なJSONの場合、重複判定・状態管理コンポーネントはエラーを呼び出し元に通知し、空扱いにしない |
