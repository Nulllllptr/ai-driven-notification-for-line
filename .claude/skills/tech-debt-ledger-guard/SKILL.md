# 技術的負債台帳ガード

`implementation-rules.md`のADRは「決定の記録」を扱う。本スキルは「未解決のまま残っている負債の
記録」を扱う。`TECH_DEBT_LEDGER_TEMPLATE.md`をコピーした`TECH_DEBT_LEDGER.md`に追記する。

## 1. 記録するタイミング

妥協した実装をした直後、または既存コードの負債に気づいた直後に、開発者へ記録の提案を1回行う。
断られたら記録しない。

## 2. 記録する項目

- 日付
- 場所(ファイル名:行番号)
- 内容(何を妥協したか)
- 影響(放置するとどうなるか)
- 優先度(高/中/低)
- 状態(未着手/対応中/解消済み)

## 3. 分類(4象限)

解消コストと放置した場合の影響の2軸で優先度を判断する。

- 高影響・低コスト: 最優先で解消する
- 高影響・高コスト: 計画的に解消時期を決める
- 低影響・低コスト: 気づいたときに解消する
- 低影響・高コスト: 記録だけして無理に解消しない

## 4. 棚卸し

台帳の項目が増えてきたら、定期的に「状態」が古いまま止まっている項目がないか確認する。
解消済みの項目は削除せず「解消済み」として残し、いつ・どう直したかが追えるようにする。
