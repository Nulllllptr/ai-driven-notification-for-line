# APIライフサイクルガード

外部境界の一覧化は`implementation-guard`が扱う。本スキルは、その境界(API)を変更・廃止する際の
規律を扱う。

## 1. 破壊的変更かどうかの判定

既存のAPI利用者に影響する変更(フィールド削除・型変更・必須化・エンドポイント削除・意味の変更等)は
破壊的変更として扱う。フィールド追加や新エンドポイント追加は基本的に非破壊的。

## 2. バージョニング方針

破壊的変更が必要な場合、既存バージョンを維持したまま新バージョンを追加する(URLパス/ヘッダ等の
方式はプロジェクト内で統一する)。旧バージョンの廃止時期を明示し、利用者に事前告知する期間を設ける。

## 3. コントラクトテスト

API提供側の変更が、利用側(他サービス・フロントエンド)の期待する形式を壊していないかを検証する
テストを、可能な範囲で用意する。E2Eテストだけに正しさの確認を委ねない。

## 4. レート制限・悪用防止

外部に公開するAPIには、想定利用量を踏まえたレート制限を設ける。特に認証・パスワードリセット等の
エンドポイントは、総当たり攻撃を想定した制限を優先的に設計する(`security-guard`の認可観点と併せて
確認する)。

## 5. 対象外

特定のAPI Gatewayやフレームワーク固有の設定方法はここでは扱わない。原則のみを扱う。
