# シークレットライフサイクルガード

`security-guard`は平文混入の検知を扱う。本スキルはシークレットが発行された後の運用
(ローテーション・失効)を扱う。

## 1. ローテーション方針

- 各シークレットにローテーション頻度を定める(例: 90日ごと)。頻度が未定のシークレットは、
  まず「未定」であることを明示したうえで、頻度を決める
- ローテーションは自動化を優先する。手動運用に頼ると実施されないまま放置されやすい

## 2. 失効手順

- 漏洩が疑われる、または不要になったシークレットは速やかに失効・再発行する
- Git履歴に一度でも入ったシークレットは、削除しても履歴に残るため、値の失効・再発行以外に
  対処法がない(`release-review-guard`のシークレット観点と同じ考え方)

## 3. 権限の失効

チームメンバーの離脱・契約終了時に、そのメンバーが保持していたアクセス権・シークレットを
失効させる手順をあらかじめ定めておく。手順が存在しない場合、実装せずその旨を先に指摘する。

## 4. 対象外

特定のシークレット管理サービス(Vault等)固有の操作方法はここでは扱わない。原則のみを扱う。
