# CI/CDガード

本スキルは「機械的に自動化するゲート」と「デプロイ戦略」の設計方針を扱う。
公開直前のClaudeによる目視レビューは`release-review-guard`、設計時のセキュリティ観点は`security-guard`が扱う。役割を混同しない。
具体的な閾値・ツール選定は`cicd-config.example.json`をコピーした`cicd-config.json`に定義し、本ファイルには数値を書かない。

## 1. なぜAI駆動開発でCI/CDの比重が上がるか

AI生成コードは人間が書くより速く増える。1行あたりの人間レビュー時間を減らさないと、レビューが
ボトルネックになり品質が破綻する。機械的チェックを先に通し、人間は意図・設計判断に集中できる
構成にする。

## 2. パイプラインの段階構成(既定)

1. Lint / 型チェック
2. 静的解析(SAST) + シークレット検出 — 検出時は自動ブロック(マージ不可)
3. テスト実行 + 新規コードパスのカバレッジ閾値チェック
4. AIによる自動レビュー(PRへの機械的な指摘。人間が見る前に明らかな不備を減らす)
5. 人間によるレビュー — `release-review-guard`の重大度表(Critical/High/Medium/Low)に従う
6. マージ後、進行的デリバリー(カナリア/段階的ロールアウト)でデプロイ
7. メトリクス(エラー率・レイテンシ等)を監視し、閾値逸脱で自動ロールバック

いずれかの段階が存在しないままAI生成コードの比率が増えている場合、実装を進める前にどの段階から
導入するか開発者に確認する。

## 3. 人間オーナーシップの原則

AIは提案、人は所有。セキュリティ重要箇所・複雑なビジネスロジックの変更は自動承認せず、必ず人間
レビューを経る。「(AI)ツールがそう言ったから」を承認の根拠にしない。

## 4. デプロイ・ロールバック方針

- 全量切り替えではなく、カナリア(一部トラフィックへの段階公開)を既定とする
- ロールバックはメトリクスベース(SLO逸脱等)で自動発火する設計を優先し、手動判断だけに依存しない
- 自動ロールバックの判定条件・カナリアの割合は`cicd-config.json`に定義する

## 5. 対象外

- 特定CIサービス(GitHub Actions/GitLab CI等)固有のYAML実装。プロジェクト側で用意する
- LLM推論自体の配信・評価パイプライン(モデルCI/CD)。本スキルはアプリケーションコードのCI/CDのみを扱う
