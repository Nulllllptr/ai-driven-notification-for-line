# コンポーネント設計書: ニュース収集

このコンポーネントが属するシステムは`./100-システム仕様書.md`を参照。
対応するテスト成果物は`./101-ニュース収集-テスト.md`。

## 改訂履歴
- 2026-08-19: 初版(Google News RSS検索ベース)で実装・テスト・独立レビューまで完了していたが、
  103(記事要約・生成)の実装検証で「Google NewsのRSSリンクは元記事への直接URLではなく、
  JavaScriptで動くGoogle News本体のSPA画面が返るだけで、`requests`ベースの構成では本文取得が
  できない」ことが判明した(実機検証済み)。開発者と協議の上、パブリッシャー直RSSへ切り替える方針
  (本改訂)に変更した。旧版(Google News RSS検索)の実装は破棄する。

## 1. 目的
AI駆動開発(手法・ツール動向、要件定義/レビュー人材の需要変化などの市場動向)に関する
直近6ヶ月の候補記事を、パブリッシャーが直接提供するRSS/Atomフィード(日本語・英語)から収集する。

## 2. 説明
設定済みのフィードURL一覧に対しそれぞれリクエストを行い、取得したRSS/Atom Itemを候補記事として
整形する。このコンポーネントは「候補を集めて返す」ことだけに責務を持ち、重複除外(102)・
本文取得や要約(103)は行わない。

パブリッシャー直RSSのため`link`は元記事への直接URLである(Google News RSSと異なり
リダイレクト解決が不要。101初版からの変更点であり、103の本文取得を可能にする前提となる)。

「AI駆動開発に関連するか」の絞り込みはこのコンポーネントでは行わない(フィード自体がAI関連
トピックに既に限定されているため)。関連性の最終判断は103のLLMによる記事選定に委ねる
(キーワード正規表現によるタイトルフィルタと、LLMによる意味的な関連性判断を二重に持たない
ための設計判断)。

## 3. 入力
- 呼び出し元からの引数: なし(内部設定を用いる)
- 内部設定(定数として保持): 収集対象フィード一覧。2026-08-19時点でWebFetch/実スクリプトにより
  疎通確認済み(200応答・有効なRSS/Atom・エントリの`link`が直接記事URルであることを確認)。

| 名称 | フィードURL | 言語 |
|---|---|---|
| Publickey | https://www.publickey1.jp/atom.xml | ja |
| Qiita(生成AIタグ) | https://qiita.com/tags/生成AI/feed | ja |
| Zenn(AIトピック) | https://zenn.dev/topics/ai/feed | ja |
| TechCrunch(AIカテゴリ) | https://techcrunch.com/category/artificial-intelligence/feed/ | en |
| Ars Technica(AIタグ) | https://arstechnica.com/tag/ai/feed/ | en |

検討したが不採用: ITmedia AI+・InfoQ AI/ML(候補URLを検証したところ404で、正しいフィードURLを
確認できなかったため見送り。将来、正しいURLが確認できれば追加を検討する)。

- 収集対象期間: 実行時点から過去6ヶ月

## 4. 出力
候補記事リスト(JSON配列)。呼び出し元(105オーケストレーター、後段は102)へ返す。

```json
[
  {
    "title": "記事タイトル",
    "url": "https://zenn.dev/....(直接記事URL)",
    "source": "Zenn(AIトピック)",
    "published_at": "2026-08-19T10:27:58Z"
  }
]
```

`source`はフィード設定の`名称`をそのまま用いる(個別サイトのRSS構造差異に依存しないため)。
同一記事が複数フィードでヒットした場合は`url`基準で重複を1件に統合する。

## 5. 依存コンポーネント・外部連携
- 依存コンポーネント: なし
- 外部連携: 3節の表に記載した各パブリッシャーのRSS/Atomフィード

## 6. 制約・注意事項
- 日付フィルタはフィード取得後に`pubDate`(Atomは`updated`/`published`)を解析してコード側で
  「過去6ヶ月以内」を判定する
- 6ヶ月の期間判定は暦月ではなく固定183日で近似する(ADR-0002、101・102で共通の方針)
- フィード提供元のサイト構成変更・一時的な障害によりフィード取得が失敗する可能性がある。
  個別フィードの失敗は当該フィードをスキップして継続し(AC-4)、全滅時のみエラーとする(AC-5)
- Publickeyは他フィードほどAIトピックに厳密に限定されていない(技術ブログ全般)ため、
  AI駆動開発と無関係な候補が混ざる可能性がある。厳密なキーワードフィルタは設けず、
  103のLLMによる記事選定で関連性の低い候補を除外する設計とする(2節参照)

## 7. 受け入れ条件(EARS形式)

| ID | パターン | 記述 |
|---|---|---|
| AC-1 | ユビキタス | ニュース収集コンポーネントは、設定されたフィードURL一覧それぞれについてRSS/Atomを取得し、結果を統合した候補記事リストを返す |
| AC-2 | イベント駆動 | 実行されたとき、ニュース収集コンポーネントは公開日時が現在時刻から6ヶ月以内の記事のみを候補に含める |
| AC-3 | イベント駆動 | 実行されたとき、ニュース収集コンポーネントは同一`url`を持つ記事を1件に統合し、候補リストに重複を含めない |
| AC-4 | 不具合対応 | 特定のフィードのリクエストが失敗(タイムアウト・非200応答・不正なXML)した場合、ニュース収集コンポーネントは当該フィードをスキップし、残りのフィードの処理を継続する |
| AC-5 | 不具合対応 | 設定されたすべてのフィードのリクエストが失敗した場合、ニュース収集コンポーネントはエラーを呼び出し元に通知する |
| AC-6 | 不具合対応 | 公開日時が解析できない記事が含まれる場合、ニュース収集コンポーネントは当該記事を候補から除外し、処理を継続する |
