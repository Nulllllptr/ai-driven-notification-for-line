# AIエージェント運用ガード

`cost-guard`は設計・インフラのコストを扱う。本スキルはAIエージェント自体の運用(トークン消費・監査・
暴走対策・ツール権限)を扱う。具体的な上限値・エスカレーション先は`agent-ops-config.example.json`
をコピーした`agent-ops-config.json`に定義し、本ファイルには値を書かない。

## 1. トークン/実行コストの可視化

- 定型的・高頻度に実行されるAIタスクは、想定トークン消費量やコストの目安を記録する
- 同一タスクでも入力内容によって消費量が大きく変動しうることを前提に、1回あたり/日あたりの
  上限を`agent-ops-config.json`で設定する
- 上限に近づいた場合に検知できる仕組み(ログ・アラート)を用意する。気づいたら高額請求、という
  状態を避ける

## 2. 監査ログ

AIエージェントが行った変更・実行したコマンド・呼び出した外部ツールは、後から「何が/いつ/何を」
行ったか追跡できる形で記録する。最低限、次を残す(`logging-rules`の形式方針に従う)。

- 実行日時
- 実行内容(コマンド・API呼び出し等)
- 実行の起点(どの指示・どのセッションによるものか)
- 結果(成功/失敗)

## 3. キルスイッチ・エスカレーション基準

- AIエージェントに本番環境への直接的な変更権限(デプロイ・データ削除・外部送信等)を与える場合、
  即座に停止できる手段(キルスイッチ)を用意する
- どの操作がどの深刻度で、誰にエスカレーションされるかを`agent-ops-config.json`の
  `escalation.requires_human_approval`に列挙する
- キルスイッチ自体が正しく動作するか、導入時に一度実際に試す。試さないまま「用意した」だけで
  終わらせない

## 4. ツール権限の最小化(MCP等)

- AIエージェントに接続する外部ツール(MCPサーバ等)には、タスクに必要な最小限の権限だけを与える
- 「読み取り専用で十分な操作」に書き込み権限を与えない
- 新しいツール接続を追加する際、それが与える権限の範囲を1行で説明できない場合は接続前に確認する

## 5. 対象外

特定のオーケストレーションフレームワーク・MCPサーバ実装固有の設定方法はここでは扱わない。原則のみを扱う。
