# コンポーネント設計書: LINE配信

このコンポーネントが属するシステムは`./100-システム仕様書.md`を参照。
対応するテスト成果物は`./104-LINE配信-テスト.md`。

## 1. 目的
103が生成した記事(最大3件)を1件のテキストメッセージにまとめ、LINE Messaging APIの
プッシュメッセージで送信する。

## 2. 説明
LINE Messaging APIの`POST https://api.line.me/v2/bot/message/push`を`requests`で呼び出す。
エンドポイント仕様(必須ヘッダー・リクエストボディ形式・文字数上限5000字・レート制限)は
2026-08-19時点でLINE Developers公式リファレンスを確認済み。

「記事が3件未満の日は送信しない」という業務ルールは105(オーケストレーター)の責務とし、
このコンポーネントは渡された記事をそのまま送信する(0件の場合のみ、二重の安全策として
自身でも送信をスキップする)。

## 3. 入力
- `send_articles(articles: list[dict], now: datetime | None = None) -> None`
  - `articles`: 103(`generate_articles`)が返す記事リスト(`title`/`summary`/`url`/`source`)
  - `now`: メッセージ冒頭の日付表示に使う日時(省略時はJST現在時刻)。テスト時に固定するための引数
- 環境変数: `LINE_CHANNEL_ACCESS_TOKEN`・`LINE_USER_ID`(GitHub Secretsに登録、値は`docs/TECH.md`参照)

## 4. 出力
戻り値なし。成功時はLINEにメッセージが1件送信される。失敗時は`LineNotificationError`を送出する。

メッセージ本文の形式(例):
```
AI駆動開発 ニュースまとめ (2026-08-19)

■ 記事タイトル1
要約文...
https://...
(出典: Zenn(AIトピック))

■ 記事タイトル2
...
```

## 5. 依存コンポーネント・外部連携
- 依存コンポーネント: 103(記事データ形式に依存。直接呼び出しはしない)
- 外部連携: LINE Messaging API(プッシュメッセージ、`Authorization: Bearer {チャネルアクセストークン}`)

## 6. 制約・注意事項
- 1メッセージ最大5000文字(LINE仕様)。3記事×要約200字程度を想定しており通常は収まるため、
  文字数超過時の自動切り詰めは実装しない(個人小規模用途で許容できるリスクと判断。将来
  要約が長文化する場合は再検討する)
- レート制限は2,000 requests/secと十分大きく、1日1回の送信では問題にならない
- ネットワークエラー・429・5xx応答は一時的なエラーとみなし1回だけ自動リトライする。
  それでも失敗した場合、または400/401等の4xx(429を除く)応答の場合はリトライせず
  即座に`LineNotificationError`を送出する(103のリトライ方針と統一)
- チャネルアクセストークンをログに出力しない(`logging-rules.md`のmask_fields対象。
  本実装では例外メッセージにトークン自体を含めないことで担保する)

## 7. 受け入れ条件(EARS形式)

| ID | パターン | 記述 |
|---|---|---|
| AC-1 | ユビキタス | LINE配信コンポーネントは、渡された記事を1件のテキストメッセージにまとめてLINE Messaging APIへプッシュ送信する |
| AC-2 | イベント駆動 | 渡された記事が0件のとき、LINE配信コンポーネントは送信を行わない |
| AC-3 | 不具合対応 | `LINE_CHANNEL_ACCESS_TOKEN`または`LINE_USER_ID`が未設定の場合、LINE配信コンポーネントは`LineNotificationError`を送出する |
| AC-4 | イベント駆動 | LINE Messaging APIの呼び出しが一時的なエラー(ネットワークエラー・429・5xx応答)で失敗したとき、LINE配信コンポーネントは1回だけ再試行する |
| AC-5 | 不具合対応 | 再試行後も失敗した場合、または429を除く4xx応答の場合、LINE配信コンポーネントは`LineNotificationError`を送出する |
