# /goal: 自走ループ

引数(完了条件): $ARGUMENTS

対象コンポーネントの仕様書(design-doc-guardが管理する`docs/システムフォルダ/<番号>-<コンポーネント名>-仕様書.md`)
を根拠に、実装→自己評価→修正のループを、完了条件を満たすかテンプレートの停止条件に達するまで繰り返す。
判定ロジックは既存skillに委譲し、本コマンドはその呼び出し順序だけを定義する。

## 1. 開始前の確認

- 対象コンポーネントの仕様書が存在しない場合、実装を始めない。`design-doc-guard`の4節に従い
  先に仕様書を作成し、開発者の同意を得てから2へ進む
- 完了条件が引数で与えられていない場合、対象コンポーネントの仕様書「3. 入力」「4. 出力」
  「6. 制約・注意事項」から完了条件を導出する。導出した完了条件と、その根拠にした節を3行以内で
  開発者に提示してから開始する。推測のまま無言で進めない

## 2. ループ本体

1回のループで次を順に行う。

1. 実装する(仕様書に基づく。1回のループの差分は200行以内)
2. `component-test-guard`で条件網羅・機能要件・非機能要件テストを実行する
3. `code-review-guard`によるレビューを、実装を行ったのと同一のコンテキストではなく、独立した
   サブエージェント(Agent tool)を起動して実行する。実装者自身の思い込みに引きずられたレビューに
   ならないようにするため。サブエージェントには対象コンポーネントの仕様書パスと差分のみを渡し、
   正確性・重複/簡潔化/効率の指摘を返させる
4. 完了条件および仕様書(入出力・制約・受け入れ条件)と実装結果を突き合わせ、過不足がないか確認する
5. 2〜4で問題が見つかった場合、問題点を1行ずつ列挙してから同じループ内で修正し、1へ戻る
6. 問題が見つからなければループを終了し、3へ進む

## 3. 停止条件(完了条件を満たす前でも止める)

以下のいずれかに該当したら、ループを止めて開発者に確認する。推測で進めない。

- 完了条件を満たした(正常終了)
- 同じ箇所の修正が3回連続で失敗した(`implementation-guard`の撤退判断に従う)
- 通算のループ回数が5回を超えた(3回連続失敗の閾値では、成功と失敗を繰り返す振動を検知できないため)
- 1回のループの差分が200行を超える見込みになった(実装せず分割案を提示する)
- 完了条件・仕様の解釈に開発者の判断が必要な曖昧さが出た
- シークレットの平文混入、認可の欠落を検知した

## 4. 終了時の報告

- 実施したループ回数
- 各ループで見つかった問題と対応
- 最終的に完了条件を満たしたか。満たしていない場合はどの停止条件でどこまで進んだか
