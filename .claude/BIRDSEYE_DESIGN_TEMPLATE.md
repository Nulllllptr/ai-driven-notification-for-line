# 鳥瞰図設計書

プロジェクト全体を最も高い視点から俯瞰する。個々のシステムの内部詳細は
`docs/システムフォルダ/`配下のシステム単位設計書に譲り、ここでは
「何が」「どうつながっているか」「プロジェクト全体でどのルールを有効にしているか」だけを扱う。

## 1. プロジェクトの目的
このプロジェクト全体が解決する課題と、誰のためのものかを2〜3行で。

## 2. インフラ構成
クラウド/オンプレの別、主要リソース(ネットワーク・実行環境・データストア等)を箇条書きで。
未確定の間は「未確定」と明記する。推測で埋めない。

## 3. 稼働システム一覧
このプロジェクトに含まれる各システムと、対応するシステム単位設計書へのリンク。
番号は100刻み(100, 200, 300…)で新規システムに割り当てる。採番の詳細は
`docs/システムフォルダ/README.md`(採番台帳)を参照。

| 番号 | システム名 | 役割(1行) | システム単位設計書 |
|---|---|---|---|
| 100 | | | docs/システムフォルダ/100-システム仕様書.md |

## 4. 大まかな入力から出力までの流れ
システム間をまたぐデータ・処理の流れを、どこから入り(入力元)、どのシステムを経由し、
どこに出る(出力先)かの単位で記す。可能であれば構成図(HTML/Mermaid)へのパスをここにリンクする。
未実装の間は「未実装」と明記する。

## 5. 開発方針(このプロジェクトで有効なユニット)
`.claude/skills/` `.claude/rules/` のうち、このプロジェクトで有効化しているものを列挙する。
プロジェクト全体で1つの表とし、システムごとに重複させない。

| ユニット | 有効/無効 | 補足 |

| security-guard | | |

| client-doc-guard | | |
